# 電池(バッテリー)について

## 起きたこと（調査と修正）
遊んでいると電池の減りが異様に早い、という報告を受けて、ブラウザのCPU使用量を実測しました
（スマホ並みの画素数 375×667・3倍密度で、画面を8秒そのまま表示。ブラウザ全体のCPU時間を測定）。

| 画面 | 修正前 | 修正後 |
|---|---|---|
| ホーム | 約78% | **約0%**（タイトルが止まった後） |
| しりとり（プレイ中） | 約88% | **約4.5%** |
| 漢字検定（プレイ中） | 約85% | **約4.5%** |
| 音の準備（無音のまま放置） | 約3.5% | **0%**（8秒で停止） |

### 原因と対策
1. **背景の落書きが、無限に動いていた**（ほぼ全部の原因）。全画面のSVG「ゆがみフィルタ」の上で動かしていたため、毎フレーム画面全体のフィルタを計算し直していた。
   → **動かさない**（静止していれば一度描くだけ）。
2. **タイマーのバーを、幅(width)で0.1秒ごとに動かしていた**（約8ポイント）。幅を動かすとレイアウト計算が毎回走る。
   → **transform:scaleX を1秒に1回更新**（`Fx.timerBar`）。滑らかに動かし続けるとそれも電池を使うので、**1秒ごとの段階的な表示**にした。
3. **音の準備(AudioContext)を、動かしたままにしていた**（約3.5ポイント）。無音でも電池を使い、iPhoneでは省電力に入りにくくなる。
   → **無音が8秒続いたら止め**、次に鳴らす時に再開（`js/sfx.js`）。アプリが裏に回ったらすぐ止める。
4. **タイトルのゆらゆらが無限だった**（約7ポイント。落書きの陰で見えていなかった）。→ **2回だけ**動かして止める。
5. タイマーの確認の間隔を 0.1秒→0.25秒（表示は1秒ごとにしか書きかえない）。

## 今後の注意（電池にやさしく作るために）
- **ずっと動き続けるもの（`animation: … infinite`、常に回る `setInterval`／`requestAnimationFrame`）を作らない**。見ていなくても電池を使う。
- 動かすなら、**`transform` と `opacity` だけ**（レイアウトや再描画を起こさない）。幅・高さ・位置(left/top)・フィルタは動かさない。
- **全画面にかかるSVGフィルタ（`feTurbulence` など）は、動くものの下に置かない**。静止した背景としてなら問題ない（一度描けば使い回される）。
- 音の準備（AudioContext）は、鳴らさない間は止める。
- 測り方: ブラウザを起動し、画面を放置して、ブラウザの全プロセスのCPU時間（`/proc/<pid>/stat` の utime+stime）の増え方を比べる。
  変更の前後で「じっと表示している間のCPU使用率」を比べると、電池への影響の目安になる（実機のバッテリー量そのものではない）。

## 残っているもの
- 読み入力欄のカーソルの点滅（約2ポイント程度）と、時間切れ判定の0.25秒ごとの確認は残してある。
- 効果音やアニメーションは、**動かすのは一瞬だけ**（紙吹雪は約4秒、揺れ・弾みは0.4秒程度）。
- 「動きを減らす」設定（OS）をオンにしている人には、アニメーションと紙吹雪を出さない（これまでどおり）。
